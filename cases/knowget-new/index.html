Codex SSR · 官方骑士

OpenAI 出品 · Rust 编写 · 开源 · 终端里的「可审查、可验证、可回退」开发循环

🧠 原理拆解

Codex 不是「终端里的 ChatGPT」，而是一个本地终端 AI 编程 Agent：它把 AI 从「离线建议者」变成「在工程里干活的协作者」。核心链路：

📂 读取工作区
+ Git 状态
→
📝 AGENTS.md
项目规则
→
💬 你下达
自然语言任务
→
🔍 搜文件
定修改方案
→
🛡️ 沙箱内改文件
跑命令
→
👀 你审查 diff
决定去留
↩️ 测试 / 编译失败则回填结果继续修正 —— 循环直到任务完成
🛡️ 双重安全盾沙箱（sandbox_mode）管「能碰什么」，审批（approval_policy）管「要不要先问你」，两轴组合出精细权限。
🧠 三级记忆AGENTS.md 分全局（~/.codex/）、项目根、子目录三层，越靠近越优先，让 AI 记住项目规范。
⚙️ TOML 配置一切配置集中在 ~/.codex/config.toml —— 注意是 TOML 格式，不是 JSON！

📖 新手试炼（使用教程）

1
安装铠甲

npm 全局安装（也可用 brew 或 GitHub Releases 下载二进制）：

Terminal
$ npm i -g @openai/codex
2
登录认证（二选一）

推荐 ChatGPT OAuth 登录（Plus / Pro / Business 等订阅均含 Codex 额度），或改用 API Key：

Terminal
$ codex login                    # ChatGPT 账号 OAuth 登录
$ export OPENAI_API_KEY=sk-...  # 或改用 API Key
3
三种启动姿势
Terminal
$ codex                          # 交互式 TUI 模式
$ codex "fix lint errors"        # 带初始任务启动
$ codex exec "explain utils.ts"  # 非交互自动化（适合脚本/CI）
4
切换模型与推理强度

会话内用 /model 命令，或启动时指定 gpt-5-codex 系列模型并调节推理强度：

Terminal
$ codex -m gpt-5-codex -c model_reasoning_effort="high"
# model_reasoning_effort 可选 low / medium / high
5
推荐权限组合（写进 config.toml）
~/.codex/config.toml
# 日常开发（社区公认的安全默认值）
sandbox_mode    = "workspace-write"
approval_policy = "on-request"

沙箱四档：read-only / workspace-write / danger-full-access；审批四档：untrusted / on-request / on-failure / never。

⚠️ 副本陷阱（注意事项）

🕳️
配置是 TOML，不是 JSON从 Claude Code / dsh 迁移过来的玩家最容易踩：Codex 的 config.toml 用 key = "value" 语法，写 JSON 大括号直接报错。
☢️
别对生产仓库开核弹模式--dangerously-bypass-approvals-and-sandbox 会同时拆掉沙箱和审批两道盾，只适合一次性容器/虚拟机里使用。
👀
diff 必须亲自审查「可审查」是 Codex 的核心价值。Agent 改完代码先看 diff 再放行，养成肌肉记忆。
🔑
最小权限原则按任务给权限：只做代码审查用 read-only，要改代码再上 workspace-write，别一上来全开。

🧩 扩展装备（插件 / 技能 / MCP）

🔌 MCP：config.toml 里挂载

在 ~/.codex/config.toml 中添加 [mcp_servers.名字] 段，填 command 与 args，即可让 Codex 调用 GitHub、浏览器、数据库等外部工具服务器。

📜 Skills：放进技能目录

把带说明的技能文件放到 ~/.codex/skills/，Codex 会在合适时机自动加载对应工作流（如代码审查、提交规范）。

🤝 Subagent：配置专属代理

在 config.toml 的 [agents.名字] 中定义子代理（如 code-reviewer），主 Agent 可把审查、测试等任务委派出去并行处理。

Claude Code SSR · 生态之王

Anthropic 出品 · 终端 agentic 编程工具 · 60+ 斜杠命令 · 技能/Hooks/子代理/插件全家桶

🧠 原理拆解

Claude Code = 工具调用循环 + 分层记忆 + 权限模式管控。它的两大「行为控制术」值得单独记住：

📂 沿目录树向上
发现 CLAUDE.md
→
🧠 读取项目规范
进入上下文
→
💬 你提需求
→
🔧 读/写/编辑文件
跑 Shell · 搜索
→
🛡️ 权限模式
逐项把关
→
✅ 交付结果
↩️ 期间每个生命周期节点（工具调用前后、会话启停…）都可被 Hooks 钩住做确定性控制
📜 CLAUDE.md = 建议性（约 80% 遵循）项目规范写在里面，模型「参考着做」；适合放构建命令、代码风格、Git 流程。
🪝 Hooks = 确定性（100% 执行）必须每次都发生的规则（自动格式化、拦截危险命令）交给生命周期钩子，连 bypassPermissions 都拦得住 PreToolUse 的 deny。
🎚️ 五档权限模式default / acceptEdits / plan / bypassPermissions / auto，会话中 Shift+Tab 循环切换，风险逐级变化。

📖 新手试炼（使用教程）

1
安装与启动
Terminal
$ npm install -g @anthropic-ai/claude-code
$ claude        # 在项目目录运行，进入交互式会话

需要 Anthropic 订阅（Pro/Max）或 API Key。

2
三种使用姿势
Terminal
$ claude                              # 交互式（日常开发）
$ claude -p "explain this codebase"  # 管道模式（脚本/CI）
$ claude /plan 先做计划再动手           # 计划模式
3
必学斜杠命令
Claude Code 会话
/model      # 切换模型
/hooks      # 浏览/管理生命周期钩子
/mcp        # 管理 MCP 服务器连接
/teleport   # 把当前会话"传送"到网页端继续（订阅者）
4
给王者写「记忆」—— CLAUDE.md

在项目根目录创建 CLAUDE.md，写清构建命令、代码风格、Git 流程。最佳实践：单文件 < 200 行；大项目拆到 .claude/rules/；monorepo 分层放置。

CLAUDE.md
## Build & Run
- Install: pnpm install
- Dev server: pnpm dev
- Lint: pnpm lint --fix

## Code Style
- TypeScript strict mode, no any
- Prefer const over let
5
上第一个 Hook：保存即格式化
.claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npx prettier --write $FILEPATH" }
        ]
      }
    ]
  }
}

每次 Edit/Write 之后自动跑 prettier —— 这就是「确定性」的味道。

⚠️ 副本陷阱（注意事项）

🪝
Hooks 拥有你的全部权限钩子会以你的用户身份执行任意 shell 命令且无确认弹窗。只安装可信来源的 Hooks，防止数据外泄与误删。
🚀
bypassPermissions 慎用跳过所有权限确认等于把方向盘交给 AI；确需使用时，务必配合 Hooks 设置不可协商的红线（如禁止删生产分支）。
📖
CLAUDE.md 不是越长越好超长文件烧上下文还会降低指令遵循度。控制在 200 行内，多余规则拆进 .claude/rules/。
🔁
改 Hooks 配置要重启除通过 /hooks 面板修改外，手工编辑 settings.json 后需重启会话才生效。

🧩 扩展装备（插件 / 技能 / MCP）

🔌 MCP：claude mcp add
Terminal
$ claude mcp add playwright -- npx @playwright/mcp@latest

支持 MCP Tool Search 懒加载：工具定义用到才载入，挂 10+ 服务器也不撑爆上下文。

📜 Skills：~/.claude/skills

每个技能一个目录 + SKILL.md（frontmatter 写描述与触发时机）。会话中输入技能名或让 Claude 自动匹配调用，还能热重载即时生效。

🤝 Subagents：.claude/agents

在项目 .claude/agents/ 下定义专属子代理（架构师、测试员…），各自独立上下文与工具白名单，主代理按需委派。

🧩 Plugins：插件市场

插件 = 技能 + 命令 + Agents + Hooks + MCP 的打包合集，从 marketplace 一键安装整套工作流，团队配置可分发。

pi SR · 极简刺客

Mario Zechner (badlogic) 出品 · MIT 开源 · 极简终端编码 harness · 「核心小到能装进脑子」

🧠 原理拆解

pi 的武功只有一招：把复杂度砍到骨头。它相信现代模型已被 RL 训练得足够懂编码，harness 不该啰嗦：

💬 你说需求
→
🧠 模型思考
(系统提示仅约 200 token)
→
🔧 四大工具
read / write / edit / bash
→
📄 观察结果
→
✅ 交付
↩️ 需要更多能力？装 Skills / TS 扩展，而不是换一个更重的 harness
🔪 极简对比系统提示词约 200 token（Claude Code 约 1 万），默认工具只有 4 个 —— 省下的上下文全留给你的代码库。
🔀 模型无关324+ 模型、20+ 提供商随意切换：Claude / GPT / Groq / Gemini / 本地 Ollama，会话中途 /model 换枪。
🔫 默认 YOLO全文件系统访问 + 无权限弹窗。作者哲学：「能执行代码的 agent，任何权限门都是表演」—— 要门？自己写扩展。
🚫 不走 MCP 路线pi 的理念是用 CLI 工具组合替代 MCP 服务器，扩展走 TypeScript Extensions（25+ 事件钩子）。

📖 新手试炼（使用教程）

1
安装这把薄刃
Terminal
$ npm install -g --ignore-scripts @openeryc/pi-coding-agent
# --ignore-scripts 关闭依赖生命周期脚本，pi 正常使用不需要它们
2
配钥匙，然后开打
Terminal
$ export ANTHROPIC_API_KEY=sk-ant-...   # 任一提供商的 Key
$ pi                                    # 直接开聊；或进入后 /login 选择提供商
3
会话内常用操作
pi 会话
/model    # 中途切换模型（如切到本地 Ollama 省钱）
/login    # 切换/登录提供商

会话支持分支（从任意节点岔出新方向）与压缩（长会话自动瘦身）；还有 print/JSON、RPC、SDK 四种运行模式供程序化集成。

4
装一个社区扩展包试试水
Terminal
$ pi install npm:pi-ca-leash   # 例：用 pi 编排 Claude Code / Codex 的扩展
$ pi update --all              # 更新 pi 与所有扩展包

⚠️ 副本陷阱（注意事项）

🔫
YOLO 默认全放行没有「允许此操作？」弹窗，agent 拥有完整文件系统与命令执行权。重要项目先写 TypeScript 扩展自建权限门，或在虚拟机里玩。
📦
第三方包 = 可执行代码pi 包能执行任意代码并影响 agent 行为，安装前务必阅读源码，只装信任作者的包。
🖥️
本地模型显存警戒线接 Ollama 时上下文长度（num_ctx）别超显存上限，否则会静默回退 CPU，工具调用可靠性骤降还不报错。

🧩 扩展装备（插件 / 技能 / 扩展包）

📜 Skills：SKILL.md 内联

技能就是一份 SKILL.md 文件，匹配时机时整份内联进提示词 —— 零代码、零编译，放进项目即可被模型使用。

🧬 Extensions：TypeScript 进程内扩展

挂载 25+ 事件钩子（会话、消息、工具调用…），可以改提示词、拦工具、加命令。官方不内置的子代理 / 计划模式，都能靠它造出来。

🎨 Themes & Prompt Templates

主题换肤 TUI 界面；提示词模板固化常用任务开场。都放进 Pi Packages 一起分发。

🚫 MCP：不支持（设计哲学）

pi 刻意不做 MCP，主张「模型直接调 CLI 工具」更简单透明。需要外部能力时，优先找对应 CLI 扩展包。

dsh SR · 新锐法师

DeepSeek Harness · 2026-08-13 开源 · 基于 Cordis · MIT 协议 · 「万物皆插件」

🧠 原理拆解

如果说 Codex 是「Rust 单体核心 + 外挂扩展」的骑士团，dsh 就是一切皆可插拔的魔法学院 —— 连 agent loop 本身都是插件：

🧩 Plugin
代码模块
→
📦 Bundle
可分发配置层
→
🏠 Profile
可启动组合
→
🩹 Patch
配置覆盖层
→
🚀 启动！

🛋️ 装修比喻：Plugin 是家具，Bundle 是家具清单，Profile 是你的房子，Patch 是「把书桌挪个位置」的临时决定。

🧙 万物皆插件模型、工具、沙箱、记忆、权限、agent loop 全是插件（基于 Cordis 框架，官方称「时空可组合性」），不满意就拔下来换。
📼 Session = 事件流会话是 append-only 的 SessionEvent 事实记录，模型看到的 history 由事件投影而来；Trajectory 视图可逐事件回放全过程。
🎭 四种 Agent 预设标准（全功能编码）/ PTC Code Mode（模型写 TS 程序编排多步操作）/ 极简（仅 bash + 编辑器，跑基准）/ 创造（自定义预设）。
🧬 自进化路线Cordis 协议下模型可以自己写插件、自己装上 —— 官方描绘的「普通用户参与 AI 自进化」路线。

📖 新手试炼（使用教程）

1
检查 Node 版本（≥ 22.19）
Terminal
$ node --version   # 必须 ≥ 22.19（或 ≥ 24），Node 18 直接失败
2
一行命令召唤网页版
Terminal
$ npx @deepseek-ai/dsh web   # 或全局安装后: dsh web
# 浏览器打开 http://127.0.0.1:3080
3
首次进入的四步仪式

① 在 设置 → 模型 填 API Key（platform.deepseek.com 创建，也支持 OpenAI 兼容端点，保存即生效）；② 选择工作区（不选发不出消息！）；③ 挑一个 Agent 预设（新手选「标准」）；④ 发第一条任务。

4
Headless 模式：一条命令跑完整链条
Terminal
$ export DEEPSEEK_API_KEY=你的key
$ npx -y @deepseek-ai/dsh --profile headless "Write a Python script sales_report.py that generates a mock sales CSV and prints weekly totals. Then run it."
# 自动完成：写代码 → 执行 → 汇报结果 → 退出（适合脚本/CI）
5
管理插件
Terminal
$ dsh plugin --profile headless add 包名   # 给指定 Profile 添加插件

⚠️ 副本陷阱（注意事项）

🚧
预览版，严禁生产dsh 处于 developer preview，官方明确警告存在破坏性变更 —— 只用于学习、实验、预研。
🕵️
最隐蔽的坑：网页版默认关闭 Skills不开启时你做的技能不生效且不报错！需用 --patch enable-skills.yml 启动（CLI 版默认开启）。
🔌
3080 端口被占 = 起不来启动失败先检查端口占用（lsof -nP -iTCP:3080 -sTCP:LISTEN），杀掉残留的 dsh 进程再启。
🔑
API Key 只显示一次platform.deepseek.com 创建 Key 时务必立刻复制保存，关掉弹窗就找不回了。
📁
练手请用空目录agent 对选定工作区有读写权限，别拿真实项目当新手村地图。

🧩 扩展装备（插件 / 技能）

📜 Skills：~/.dsh/skills
Terminal
$ mkdir -p ~/.dsh/skills/hello-dsh

在目录里写一个 SKILL.md 即完成注册 —— 无编译、无安装、无重启（记得网页版要先开 skills 补丁）。

🧩 Plugins：万物皆插件的根基

模型、工具、沙箱、权限全是插件；通过 dsh plugin add 包名 安装 npm 插件，随时拔插重组，甚至让模型自己写插件。

📦 Bundles & Profiles

Bundle 打包一套插件组合便于分发分享；Profile 保存你自己的启动组合 —— 换台机器一条命令复原整个环境。

🧩扩展系统大讲堂

MCP、Skill、Plugin —— 三大天赋体系的通用修仙指南

🔌

MCP（Model Context Protocol）

给模型接外部系统的标准协议：数据库、浏览器、GitHub、Slack…… 一个 MCP 服务器 = 一组标准化工具。传输方式有 stdio / SSE / HTTP。

💡 像USB 接口：同一个外设（MCP 服务器）能插进任何支持 USB 的设备（Agent）。
📜

Skill（技能）

Prompt 工程层面的能力打包：本质是一份带说明的 SKILL.md 文件（名字 + 描述 + 触发时机 + 操作指南），零代码，模型按需加载。

💡 像武功秘籍：不用改造身体（写代码），读了就会新招式（新工作流）。
🧩

Plugin（插件）

比 Skill 更重的可执行代码扩展：能注册新工具、拦截事件、改运行时行为。各工具的分发机制不同（市场 / npm / git）。

💡 像游戏 MOD：直接改引擎行为，威力大，装前必须查来源。

🧪 实战演示：五分钟写你的第一个 Skill（以 dsh 为例）
1
建技能目录
Terminal
$ mkdir -p ~/.dsh/skills/hello-dsh
2
写入 SKILL.md（frontmatter 声明名字与触发时机）
~/.dsh/skills/hello-dsh/SKILL.md
name: hello-dsh
description: 当用户说「hello dsh」时使用。请原样输出下面的暗号，
并说明这句话来自本地文件而非训练数据。

# Hello DSH
请原样输出这一行：
**HELLO DSH — 这句话来自我电脑上的一个文件**
然后用一句话说明：它不在训练数据里，是刚从本地文件读到的。
3
网页版玩家：先解锁 skills 开关（关键！）
enable-skills.yml + 启动
# enable-skills.yml 内容：
# - id: skill-filesystem
#   disabled: false
# - id: tool-skill
#   disabled: false
$ npx @deepseek-ai/dsh web --patch ~/enable-skills.yml
4
回到对话框输入「hello dsh」

没有编译、没有安装、没有重启 —— 模型读到本地文件并输出暗号，你的第一个技能就生效了！🎉（此思路在 Claude Code / Codex / pi 中同理：写 SKILL.md → 放对目录 → 触发词调用）
