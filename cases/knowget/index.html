CH 01 / CODEX

    
codex_

    
OpenAI 官方出品的终端编码 Agent —— 先给你看 diff，再动你的代码。

    

      Apache-2.0Rust 内核上手 ★★☆☆☆适合: 批量重构 / CI
    

  


  

    

    
$▊

    
// 正在读取项目结构… 找到 47 个文件 → 生成 diff → 等待你审批…

    
[ 点击横幅可跳过打字动画 ]

  


  

    

      
      
      
      
    

    

      

        
它怎么工作：三阶段 Agent 循环

        

          
你输入任务自然语言描述目标

          
→

          
READ扫描项目 · 定位文件

          
→

          
PLAN出方案 · 生成 diff

          
→

          
你审批approval-first 关键节点

          
→

          
EXECUTE改文件 · 跑测试

        

        
    
          
  • Read → Plan → Execute：codex 先读你的代码库、找到相关文件，再规划改动，先展示 diff，等你确认后才动手写。
    • 
          
  • 审批优先（approval-first）：默认每个动作都要确认 —— 这是它和「全自动 agent」最大的区别，也是安全感的来源。
    • 
          
  • 内核级沙箱：macOS 用 Seatbelt、Linux 用 bubblewrap，从操作系统层隔离，默认封禁外网。
    • 
          
  • Rust 内核：2025.4 发布、2025.6 用 Rust 重写 —— 内存约 80MB，token 处理 240+/s，启动快、适合批量。
    • 
        

      

      

        
从安装到第一条任务

        

          步骤 1 · 安装
          

            
npm install -g @openai/codex

            
# 需要 Node.js 18+，装完用 codex --version 验证

          

        

        

          步骤 2 · 认证（二选一）
          

            
codex auth

            
# 方式 A：ChatGPT Plus/Pro 账号浏览器登录，计入订阅额度，最省心

            
export OPENAI_API_KEY=sk-...

            
# 方式 B：API key，按 token 计费

          

        

        

          步骤 3 · 第一条任务
          

            
codex "给注册接口加上邮箱格式校验，非法返回 400"

            
# 先读项目 → 出方案 → 展示 diff → 你审批 → 落地

          

        

        

          步骤 4 · 常用姿势
          

            
codex --yes "给 src/utils/ 下所有函数加 JSDoc"

            
# --yes 跳过确认，适合脚本 / CI 一次性任务

            
codex --context src/api/users.ts "给这个文件写集成测试"

            
# --context 指定要参考的文件，大项目防迷路

            
cat error.log | codex "分析这个报错并给出修复建议"

            
# 管道把上下文喂给它

          

        

        

          步骤 5 · 三种审批模式
          

            
codex --approval-mode full-auto "重构所有测试改用 vitest"

            
# suggest（默认）全部要确认 · auto-edit 自动编辑但跑命令要确认 · full-auto 全自动（适合 CI）

          

        

        
💡 首次使用先留在 suggest 模式，摸清它的行为再考虑升级自主权。

      

      

        
避坑清单

        

          
✖
默认沙箱禁外网
需要联网的操作（下载依赖、调外部 API）默认被挡，需显式放行。

          
⚠
代码质量盲测中 Claude Code 更胜
codex 强在快和便宜，追求复杂推理质量时它不一定是最优选。

          
✖
full-auto 风险高
全自动模式适合 CI 和隔离分支，别在手边实验项目上乱开。

          
⚠
审批模式选错 = 误改文件
不熟悉时保持 suggest，让每个 diff 过你的眼睛。

        

      

      

        
原生 MCP，把外部工具接进来

        
codex 原生支持 MCP（Model Context Protocol），可以在全局配置里声明服务器：

        
# ~/.codex/config.toml
[mcp_servers.filesystem]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/allowed/dir"]

        
或者用命令直接添加：

        
codex mcp add filesystem npx -y @modelcontextprotocol/server-filesystem /path/to/dir

        
💡 每个 MCP server 支持 command / args / startup_timeout_sec / tool_timeout_sec / enabled 等配置。

        
⚠ 项目级 .codex/config.toml 只在 trusted projects（受信任项目）中生效。

CH 02 / CLAUDE

    
Claude Code_

    
Anthropic 的终端原生编码 Agent —— 读、想、改、验证，循环往复直到搞定。

    

      Anthropic三层架构上手 ★★☆☆☆适合: 复杂架构 / 精细 debug
    

  


  

    

    
$▊

    
// 读 README → 分析架构 → 3 句话回答你…

    
[ 点击横幅可跳过打字动画 ]

  


  

    

      
      
      
      
    

    

      

        
工具驱动的「读 → 想 → 改 → 验证」循环

        

          
读Read / Grep / Glob

          
→

          
想理解上下文

          
→

          
改Edit 精确编辑

          
→

          
验证Bash 跑测试

          
↺

          
迭代失败就接着改

        

        
三层架构：把上下文当资源管

        

          
Core Layer主对话上下文，共享 200K token 窗口 —— 你直接对话的地方

          
Delegation Layer子代理（最多 10 个并行），隔离上下文做探索，只把结论带回主对话

          
Extension LayerMCP · Hooks · Skills · Plugins —— 外挂能力层

        

        
    
          
  • 不是补全，是 Agent：它能读文件、写文件、跑命令、看测试结果，失败了自己迭代。
    • 
          
  • 上下文是共享的：读文件、跑命令都会消耗主对话的 200K 窗口，越用越满质量越差、越贵。
    • 
          
  • 子代理隔离：探索性工作交给子代理，主对话只收结论 —— 这是高级用法的核心。
    • 
        

      

      

        
从安装到第一条任务

        

          步骤 1 · 安装（二选一）
          

            
npm install -g @anthropic-ai/claude-code

            
# 需要 Node.js 18+

            
curl -fsSL https://claude.ai/install.sh | bash

            
# 原生安装脚本，macOS / Linux 推荐

          

        

        

          步骤 2 · 认证
          

            
export ANTHROPIC_API_KEY=sk-ant-...

            
# 加到 ~/.bashrc 或 ~/.zshrc 里长期生效

          

        

        

          步骤 3 · 进入项目开干
          

            
claude

            
# 交互 REPL 模式，像聊天一样干活

            
claude -p "给 src/utils.ts 所有函数用 Vitest 补单测"

            
# 一次性任务，跑完即退，可接入 CI / Makefile

            
claude --continue

            
# 恢复上次会话，接着聊

            
claude --model opus "这个架构怎么设计更稳"

            
# 硬任务切 opus，日常用 sonnet / haiku 省钱

          

        

        

          步骤 4 · 常用斜杠命令
          

            
/init   # 生成 CLAUDE.md 项目上下文
/compact  # 压缩会话上下文，省 token
/clear    # 清空对话

            
# CLAUDE.md 每次会话自动加载，把项目约定写进去一劳永逸

          

        

      

      

        
避坑清单

        

          
✖
上下文会「越用越满」
200K 窗口被读完的文件、跑过的命令占满后，它记不住之前的决定，质量下滑。

          
⚠
长会话 = 账单飙升
每轮请求都要把上下文全量发给模型，按 token 计费，长会话很烧钱。

          
⚠
探索别占主上下文
把搜索/读文件这类脏活交给子代理（Delegation Layer），主对话只留结论。

          
⚠
别在超大 monorepo 裸跑
用 CLAUDE.md 声明范围 + 子代理分流，否则 context 秒满。

        

      

      

        
四层扩展体系

        

          
MCPclaude mcp add 命令接入 300+ 外部服务（Git、数据库、Slack…）

          
SkillsSKILL.md 声明的领域专家能力，Claude 会自动按需应用

          
Plugins把 MCP + Hooks + Skills 打包成插件分发，装好即用

          
Hooks动作前后确定性执行的 shell 钩子，做自动化 / 审计

          
SubagentsTask 工具编排子代理，隔离上下文并行干活

        

        
claude mcp add postgres --connection "postgres://..."

        
💡 项目根放一份 CLAUDE.md，把架构、约定、测试命令写进去，每次会话自动加载。

CH 03 / PI

    
pi_

    
earendil-works 开源极简编码 Agent —— 内核只有 4 个工具，其他全靠「长出来」。

    

      MIT 开源ReAct 内核上手 ★★★☆☆适合: 想掌控一切的高级玩家
    

  


  

    

    
$▊

    
// 读取项目 → 定位配置文件 → 输出技术栈清单…

    
[ 点击横幅可跳过打字动画 ]

  


  

    

      
      
      
      
    

    

      

        
内核就十几行 ReAct 循环

        

          
调模型发出请求

          
→

          
要工具？stopReason 判断

          
→

          
执行工具read / write / edit / bash

          
→

          
结果塞回拼进上下文

          
↺

          
再调模型直到不再调工具

        

        
    
          
  • 极简内核：核心内置工具只有 read / write / edit / bash 四个，系统提示词不到 1000 token。
    • 
          
  • Turn 与 Trace：一次模型调用 + 触发的工具执行 = 一个 Turn；一整轮完整任务 = 一个 Trace。循环靠 stopReason 驱动。
    • 
          
  • 统一模型层（pi-ai）：30+ 家模型供应商统一成 12 种流式事件，想换模型改一行配置。
    • 
          
  • 能力全靠外挂：extensions / skills / prompt templates / themes 都能装，甚至可自改源码 —— OpenClaw 的底层引擎就是它。
    • 
        

      

      

        
从安装到第一条任务

        

          步骤 1 · 安装（二选一）
          

            
npm install -g @mariozechner/pi-coding-agent

            
# npm 全局安装

            
curl -fsSL https://pi.dev/install.sh | sh

            
# 一键脚本（macOS / Linux）

          

        

        

          步骤 2 · 配置模型
          

            
pi /login

            
# 或用 API key：export ANTHROPIC_API_KEY=... 后直接 pi

            
# 编辑 ~/.pi/agent/models.json
# 支持 OpenAI / Anthropic / Google / Ollama 等任意 provider

          

        

        

          步骤 3 · 开干
          

            
pi

            
# 交互模式

            
pi -p "总结这个代码库"

            
# 一次性执行，输出到 stdout（脚本友好）

            
pi --mode json   # 结构化 JSON 事件流
pi --mode rpc    # RPC 远程调用
pi --mode sdk    # SDK 集成

            
# 多种运行模式，喂给自动化管道很顺手

            
pi init   # 初始化项目配置 .pi/

          

        

        

          步骤 4 · 常用斜杠命令
          

            
/login    # 登录
/model    # 切换模型
/resume   # 恢复会话
/reload   # 重载扩展/配置
/compact  # 压缩上下文
/fork     # 分支会话
/tree     # 查看目录树

          

        

      

      

        
避坑清单

        

          
✖
GLM Coding Plan 套餐不支持 pi
别用 GLM 编程套餐的钱包去充 pi，认准它支持的 provider 列表。

          
⚠
极简 = 学习门槛
不预设子代理 / 计划模式，很多东西要自己装扩展 —— 适合想掌控一切的高级用户。

          
⚠
生态相对年轻
社区扩展包在快速涌现，遇到坑时文档可能还跟不上。

          
⚠
扩展 API 在演进
写扩展前先看对应版本的文档，别照着旧示例抄。

        

      

      

        
扩展体系：能力全靠「长出来」

        
// ~/.pi/agent/extensions/minimal-footer.ts
export default function (api: ExtensionAPI) {
  api.on('session_start', () => {
    console.log('🟢 Agent 已启动')
  })
}
# 放进目录 → /reload → 生效

        
    
          
  • Extensions：TypeScript 插件，放 ~/.pi/agent/extensions/，/reload 后生效。
    • 
          
  • Skills：可复用的提示模板 + 工具组合，打包成技能包安装。
    • 
          
  • Prompt templates / Themes：提示词模板和主题皮肤，都能定制。
    • 
          
  • Pi 包：以上所有组件打包，通过 npm / git 分享给社区。
    • 
          
  • 会话文件：持久化在 ~/.pi/agent/sessions/，可恢复、可分支。
    • 
        

        
💡 上下文文件优先级：~/.pi/agent/AGENTS.md → 父目录链 AGENTS.md → 当前目录 AGENTS.md，且兼容读取 CLAUDE.md。

CH 04 / DSH

    
DeepSeek Harness_

    
DeepSeek 开源的 Agent 运行时 —— 「一切皆插件」，连 agent 循环本身都能替换。

    

      MIT 开源developer preview上手 ★★★★☆适合: 研究 Agent 架构者
    

  


  

    

    
$▊

    
// 正在启动 Web UI @ http://127.0.0.1:3080 …

    
[ 点击横幅可跳过打字动画 ]

  


  

    

      
      
      
      
    

    

      

        
「一切皆插件」的 Cordis 插件树

        

          
Profile命名的运行组合（web / headless），决定装哪些 bundle

          
Bundle一组 Cordis 配置 + 代码，如 dsh-base / dsh-web-app

          
Plugin贡献服务、类型化事件、可逆副作用 —— 没有特权核心

        

        
    
          
  • 一切皆插件：模型适配器、工具注册表、会话日志、甚至 agent 循环本身都能替换 —— 没有特权核心需要打补丁。
    • 
          
  • 基于 Cordis：元框架提供依赖注入 + 类型化事件 + 可逆副作用，插上即用、卸载即撤销。
    • 
          
  • turn / step 模型：一个 step = 一次模型请求 + 触发的工具调用；一个 turn 可含多个 step，直到无活可干。
    • 
          
  • 会话日志是唯一事实来源：「模型可见的必须可从日志重建」—— 支持 fork、resume、回放。
    • 
          
  • 体量：约 80 个插件目录、53 个内置工具。
    • 
        

      

      

        
从一条命令到 Web UI

        

          步骤 1 · 最快启动（Web UI）
          

            
npx @deepseek-ai/dsh web

            
# 默认 http://127.0.0.1:3080

          

        

        

          步骤 2 · 源码构建
          

            
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web

            
# 需要 Node.js 22+ / Corepack 的 pnpm

          

        

        

          步骤 3 · 了解装配了什么
          

            
dsh --profile web --dump-config

            
# 打印实际启动的插件树 —— 动手前先看看机器要跑什么

          

        

        

          步骤 4 · 运行模式
          

            
Standard   # 完整工具套件
PTC        # 编程式工具调用（模型生成代码编排多轮工具）
Minimal    # 只留 shell + 文件编辑，最小验证
Creation   # 研究运行环境，手搓新模式

          

        

      

      

        
避坑清单

        

          
✖
明示会有破坏性变更
官方直接标注 developer preview：API 和配置会快速变化，按 v0.x 对待。

          
✖
别当生产标准
现在适合评估、写插件、跑实验，不适合压上核心生产链路。

          
⚠
上手门槛偏高
要理解 profile / bundle / 插件树 的概念才玩得转。

          
⚠
默认沙箱只读
sandbox-policy 默认 workspace 只读，别惊讶于「不能写文件」。

        

      

      

        
接入模型与扩展点

        
模型支持 DeepSeek + catalog providers + OpenAI-compatible 自定义端点（可接本地模型）：

        
# cordis.yml 片段
plugins:
  llm-deepseek:
    apiKeyEnv: DEEPSEEK_API_KEY
    baseURL: https://api.deepseek.com
    thinking: enabled

        
    
          
  • 扩展点 = 事件系统：模型适配器、工具注册表、会话日志、agent 循环都可插拔替换。
    • 
          
  • 会话即制品：Trajectory 视图可回放、分支、续跑 —— 调试 agent 行为的好工具。
    • 
          
  • 可接本地模型：用自定义 baseURL + 模型定义走 OpenAI-compatible 协议。
    •
